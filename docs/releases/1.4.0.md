# PromptSonar 1.4.0

**Theme: PromptSonar explains the execution path — not just the finding.**

This release bundles the last several engine sprints into a single, consistent
release across all distribution surfaces (Core → CLI → SARIF → Playground).

## New

- ✅ **MCP Safety Engine v2**
- ✅ **Workflow Provenance**
- ✅ **Confidence Scoring**
- ✅ **Root Cause Analysis**
- ✅ **Workflow Diff Engine**

PromptSonar now explains:

- **where** execution can go (workflow path → privileged sinks)
- **why** the path exists (per-node/edge provenance from real rule matches)
- **confidence** in the path (deterministic 0–100 score + LOW/MEDIUM/HIGH)
- **how remediation changes the path** (before/after diff + risk reduction %)

## Highlights

### MCP Safety Engine v2
Detects automatic tool execution, wildcard permissions, filesystem/shell/network
capabilities, host credential propagation, chained MCP execution, privilege
escalation paths, and approval bypass — each contributing to a per-server **MCP
Risk Score** (LOW/MEDIUM/HIGH/CRITICAL). New rules `MCP-103/104/105/107/108/109`
extend the existing `MCP-001…014` namespace without renumbering. See
[docs/rules.md](../rules.md).

### Workflow Provenance & Confidence
Every workflow node and edge carries the evidence and rule matches that produced
it, plus a deterministic confidence contribution. The path exposes
`confidence_score` (0–100) and `confidence_level`.

### Root Cause Analysis
Related findings are grouped under the single finding that best explains them;
the rest are surfaced as **supporting findings**. Nothing is deleted or
suppressed — this is organization only.

### Workflow Diff Engine
For any path that reaches a privileged sink, PromptSonar attaches a
`workflow_diff`: the dangerous **before** graph vs the hardened **after** graph,
exactly which nodes/edges were removed, an `executionPathRemoved` verification,
a `diffReason` classification, and a deterministic `riskReduction` %. The
contract is versioned (`workflow_diff_version: "1.0"`). See
[docs/workflow-diff.md](../workflow-diff.md).

## Surfaces updated

| Surface | What changed |
| --- | --- |
| **Core** (`@promptsonar/core`) | Source of truth for all of the above. |
| **CLI** (`@promptsonar/cli`) | Human output now shows Execution Path Confidence, Root Cause + Supporting, and Workflow Diff (Execution Path Removed / Risk Reduction). JSON and SARIF carry the full structured data. |
| **SARIF** | Adds `confidence_score`, `confidence_level`, `root_cause`, `supporting_findings`, MCP risk metadata, and `workflow_diff` (version, reason, risk reduction, removed nodes/edges, before/after risk). Backward compatible — new optional property-bag keys only. |
| **Playground** | The existing "Execution Path Removed" section renders real diff data (no redesign). |

## CLI example

```text
PromptSonar v1.4.0 — scanning mcp.json

  🔴 CRITICAL   MCP-104
     ...
     AI Workflow Path:
       mcp_server
         -> privileged_tool
         -> shell_execution
     Execution Path Confidence: 95% (HIGH)
     Risk: mcp server -> privileged tool -> shell execution is a critical workflow path.
     Workflow Diff:
       ✓ Execution Path Removed
       Risk Reduction: 95% (100 -> 5)
       Removed Nodes: mcp server, privileged tool, shell execution

  Root Cause:
     MCP Tool Poisoning
  Supporting:
     - Workflow Escalation
     - Privileged Sink Access
```

## Compatibility

- All new data is **additive and optional**. Existing scans, old SARIF reports,
  and consumers that don't read the new keys are unaffected.
- New shapes ship under explicit version fields (`workflow_diff_version`) so
  future evolution won't break consumers.

## Validation

- `npm run build`, `npm test`, `npm run lint` all pass with no regressions.
