# PromptSonar 1.5.1

Correctness and packaging release. No changes to the detection engine's findings
other than the OWASP identifiers noted below.

## Packaging

- **Published packages now always ship a fresh build.** `@promptsonar/core`,
  `@promptsonar/cli` and `@promptsonar/claude-code` gained a `prepublishOnly`
  script that removes `dist/` (and the TypeScript build cache) and rebuilds from
  source before publishing.

  This fixes a real defect: the published 1.5.0 packages contained compiled
  output from an earlier build. `promptsonar --version` reported `1.4.3` from a
  package whose manifest said `1.5.0`, and none of the 1.5.0 compliance work was
  present in the shipped bundle. Because no build ran at publish time, whatever
  happened to be in `dist/` on the publishing machine was what shipped.

  1.5.1 is the first release built by this hook.

## Compliance evidence

- **ISO/IEC 42001 controls are derived per finding.** The Article 19 export
  previously tagged every record with a single hardcoded `ISO42001-6.2`, so the
  export carried no information about what was found. Controls are now derived
  from the findings themselves — privileged execution and tool approval evidence
  A.9.2 / A.6.2.6, injection and evasion evidence A.6.2.4, credential exposure
  evidences A.7.2, efficiency evidences A.6.2.6, ethics evidences A.5.2, and the
  quality categories evidence A.6.2.2. Clause 6.2 remains as a baseline tag.

  Controls are sorted and waived findings no longer contribute, so the export is
  byte-stable for the same input.

  These tags record which control a finding is *evidence for*. They do not assert
  conformity: PromptSonar supports evidence collection and does not determine or
  certify whether a system is compliant.

- **SARIF rules expose `properties.tags`.** The OWASP mapping previously reached
  only `properties.owasp`, while `tags` was empty on every rule — the field that
  consumers such as GitHub code scanning filter on.

## OWASP mapping

- **LLM06 and LLM10 are now mapped.** `sec_workflow_escalation`,
  `sec_privileged_sink_access` and `sec_mcp_tool_poisoning` report **LLM06
  Excessive Agency**; `eff_token_budget` and `eff_token_bloat` report **LLM10
  Unbounded Consumption**. Neither identifier existed anywhere in the project
  before this release.

- **Standardized on the OWASP LLM Top 10 (2025).** The project previously mixed
  taxonomy versions: LLM06/LLM10 use 2025 naming while `sec_unbounded_access` and
  `sec_rag_injection` reported `LLM07` under the 2023 meaning ("Insecure Plugin /
  Tool Design"). In the 2025 list LLM07 is System Prompt Leakage, which neither
  rule detects.

  **Breaking for consumers that filter on OWASP identifiers:**

  | Rule | Before | After |
  | --- | --- | --- |
  | `sec_unbounded_access` | `LLM07` | `LLM06` Excessive Agency |
  | `sec_rag_injection` | `LLM07` | `LLM08` Vector and Embedding Weaknesses |

  No rule reports `LLM07` any more. Update any saved SARIF queries or dashboards
  that filtered on it.

## CLI correctness

- **`--fail-on` no longer fails open.** Any unrecognized value — a typo such as
  `hgih`, or an uppercase `HIGH` — previously returned exit code 0, silently
  passing a build that contained critical findings. Values are now normalized
  (case- and whitespace-insensitive, so `HIGH`, `High` and ` high ` behave
  identically) and validated; an unrecognized value prints a clear error and
  exits non-zero. An empty value falls back to the fail-closed `critical`
  default.

- **The policy-file schema error now documents a usable format.** The "Invalid
  schema" message recommended `policies[].name` with `rules.max_critical`, none
  of which exist in the schema — a user who followed it was rejected again. The
  message now shows the real schema (`id`, plus optional `match`, `thresholds`,
  `block_patterns`, `require`) and lists the specific validation problems. A
  regression test feeds the documented example back in and asserts it is
  accepted.

## Dashboard

- **`/mcp-audit` discloses that it shows demo data.** The page renders fixed
  example servers and findings, but presented them as though they were a real
  audit — the header implied it inspected "your local environment" and a
  "Trigger Local Fuzzer" button ran a scripted simulation without saying so. It
  now carries a persistent banner, the copy states that nothing on the page
  inspects your machine and points to `promptsonar audit-mcp`, and the fuzzer is
  labelled as a simulated walkthrough. The placeholder credential was replaced
  with an obviously non-real value.
